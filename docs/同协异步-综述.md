# 同协异步：一份综述

> 副标题：没有中心，一群各自为政的个体，能不能长出稳定的整体
>
> 版本 0.1 ｜ 2027-11 ｜ 作者：彭馨田（fanqin314）
>
> 本文是"同协异步"这条思考线的第一次文献收口。它不是一个新算法，而是把同一个问题在四个学科里已经被问过的部分拼起来，并指出**还没被回答的那一小块**。

---

## 摘要

"同协异步"指：多个异构个体，各自进度、各自方法，去完成一个统一目标。

把这句话拆开，它同时落在四个已经有几十年积累的领域里：**共识理论**回答了"异步 + 掉线时还能不能达成一致"；**群体智能与编队控制**回答了"纯局部规则能不能长出全局秩序"；**去中心化训练与推理**回答了"把模型摊到一群普通设备上，代价是多少"；**公地治理**回答了"一群自私的人能不能自己管好共享资源"。

四个领域各自有结论，但它们的**交叉点**是空的：共识理论假设节点是诚实且算力对等的；群体智能不关心每个个体的成本；去中心化训练假设参与者有动机；公地治理不涉及技术实现。

本文的贡献是三件事：

1. 把"同协异步"形式化成三个可测的问题（第 3 节）；
2. 给出四条脉络的最小必要知识，并标明每条里**哪一段必须读、哪一段可以跳过**（第 2 节）；
3. 给出一个两小时能跑完的仿真实验设计，用它可以得到第一批自己的数字（第 5 节）。

本文不对"免费 AI 能否实现"下结论。已有的实测数据（第 4 节）表明：在公网条件下，按层切分的推理会被网络税吃掉绝大部分收益。这是本文的出发点，不是它的结论。

---

## 1. 问题的形状

先把"同协异步"写成人能检查的句子：

> 有 N 个个体。每个个体有自己的速度、可靠性和"愿意投入的程度"。它们只通过有限的消息互相看见。没有任何个体知道全局状态。它们要共同完成一个目标，并且**允许各自的进度不同**。

这个描述里有四个变量，恰好对应四条文献脉络：

| 变量 | 问的是什么 | 对应领域 |
|---|---|---|
| 异步 + 掉线 | 还能不能达成一致 | 分布式共识 |
| 只看得见邻居 | 局部规则能否长出全局结构 | 群体智能 / 编队控制 |
| 摊到普通设备上 | 通信与算力的代价 | 去中心化训练与推理 |
| 愿意投入多少 | 自私与搭便车 | 公地治理 / 激励机制 |

**一个容易被忽略的区分**：这篇综述讨论的是"**协调**"（coordination），不是"**计算**"。协调不产生新的算力，它只决定已有的算力怎么被组织。这一点在第 4 节会变成一个硬数字。

## 2. 四条脉络

### 2.1 共识理论：异步是有代价的

**起点是 FLP（1985）**：在一个完全异步的系统里，只要有一个进程可能崩溃，就**不存在**一个确定性的算法能保证达成共识 [1]。这不是工程问题，是定理。

这条路被三个方向绕开了：

- **放宽时间假设**：部分同步（partial synchrony）。Dolev、Dwork、Stockmeyer 证明，只要对"消息延迟"或"进程速度"加一点点假设，就能容忍故障 [2]。这是 Paxos、Raft 这类协议的现实基础 [3][4]。
- **放宽确定性**：随机化。Ben-Or 证明抛硬币可以让异步共识以概率 1 终止 [5]。
- **把"检测失败"本身做成抽象**：失败检测器（failure detector），Chandra 与 Toueg 用 ◇S 这类检测器把 FLP 绕过去 [6]。

**拜占庭故障**是另一条线：Lamport、Shostak、Pease 的"拜占庭将军"给出 3f+1 的下界——想容忍 f 个说谎者，至少要有 3f+1 个节点 [7]。

**和"同协异步"的关系**：这一支给出了**下界**，也就是"你必须付出什么"。它告诉我们"完全无中心 + 完全异步 + 有节点掉线"在严格意义上是做不到确定一致的。所以现实里的方案全部是"加一点点东西"：时间假设、随机性、失败检测器，或者一个轻量账本。

**必读与可跳过**：FLP 只需要读结论（一页）；Dolev 那篇读它的分类表就够了；拜占庭只读 3f+1 的推导。

### 2.2 群体智能：局部规则长出全局秩序

**boids（Reynolds, 1987）** 是原型：每只鸟只做三件事——保持距离、对齐方向、向中心靠拢——整群鸟就飞出了队形 [8]。

**Vicsek 模型（1995）** 把它变成物理：自驱动粒子，每个只看邻居的平均方向，加一点噪声。系统会从"无序"突变到"有序"，是一个真正的相变，序参量随噪声和密度变化 [9]。

**编队控制**把它变成工程：Jadbabaie 等人证明，只要邻居图在时间上"足够连通"，最近邻规则就能让一群移动个体收敛到同一方向 [10]；Olfati-Saber 等人的综述把这类结果统一成"一致性协议" [11]。

**和"同协异步"的关系**：这一支给出了**上界**，也就是"最少需要多少信息"。答案是惊人地少：三个局部规则、看不见全局、没有中心。

**但要注意它的隐含假设**：这些模型里，每个个体都是**同质的、诚实的、永远在线的**。Vicsek 的粒子不会偷懒，也不会中途退出。这正是"同协异步"要补的那一块。

### 2.3 去中心化训练与推理：代价是通信

这一支最接近工程现实，也最接近"算力群"的原始想法。

- **FedAvg（McMahan et al., 2017）**：把梯度在本地算、只上传参数，通信量降一到两个数量级 [12]。它假设有一个中心服务器。
- **Swarm Learning（Nature, 2021）**：去掉中心服务器，用区块链做点对点协调，在临床数据上验证了可行性 [13]。
- **Learning@home / DeMo（NeurIPS 2020）**：正面回答"能不能用十万台家用电脑训练大模型"。结论是：可以，但只能用 MoE 这种**稀疏激活**的结构，因为稠密模型要求所有设备同步，而家用网络做不到 [14]。
- **Hivemind 与 Petals（NeurIPS 2021 / ACL 2022）**：把模型按层切开，不同机器各持一段，推理时串起来；Petals 进一步开放成公共 swarm，任何人都可以加入提供算力 [15][16]。

**和"同协异步"的关系**：这一支已经把你想要的东西做出来了——**作为系统**。它没做的是：让参与者有动机、让异构的弱设备也能贡献、让"进度不同"成为常态而不是故障。

**它的硬结论，也是本文最重要的一条**：按层切分只增加**容量**，不增加**速度**，因为层是严格串行的。稠密模型在公网上跨设备推理，延迟税会吃掉几乎全部收益。

### 2.4 公地治理：一群自私的人能不能自己管好

**Hardin（1968）** 的"公地悲剧"说：共享资源必然被耗尽 [17]。

**Ostrom（1990）** 用几十年田野研究反驳了它：真实世界里，人们**能**自己管好公地，但有八个设计原则——清晰的边界、与当地条件相符的规则、集体选择、监督、渐进的惩罚、冲突解决机制、对组织权的认可、嵌套的层级 [18]。

**BitTorrent（Cohen, 2003）** 是技术侧的对照：用"tit-for-tat"（你给我我才给你）让陌生人互相服务，不需要信任 [19]。

**和"同协异步"的关系**：这一支回答的是"**动机**"这个技术文献集体回避的问题。它给出的答案是：不需要道德，只需要**让搭便车在机制上不划算**。

## 3. 三个可检验的命题

把四条脉络交叉，得到三个可以用仿真在几小时内回答的问题。每个都写成"可以被证伪"的形式。

**命题一（协调的必要量）**
> 存在一个邻域大小 k，使得纯局部规则（无任何全局信息）足以在异步更新下形成稳定队形；k 再小则不能。

检验方式：固定 N，扫 k=2,3,5,8，记录形成队形的成功率与步数。

**命题二（自私的临界点）**
> 当"偷懒节点"（收到消息但不更新）的比例超过某个阈值时，队形的维持概率会**悬崖式**下降，而不是线性下降。

检验方式：注入 5%/10%/20%/30%/50% 的偷懒节点，各跑 100 次。

**命题三（协调的性价比）**
> 一个"轻账本"（每轮只广播一个很小的摘要）带来的抗自私能力，远高于它带来的通信开销；而完整共识协议（如 PBFT 类）在这个场景下性价比为负。

检验方式：测"每节点每轮新增字节数"与"队形维持率"的比值。

这三条都不是新定理，是**可以自己测出来的经验规律**。它们的价值在于：测完之后，"同协异步"从一个想法变成一组数字。

## 4. 已有的实测数字（本仓库）

这些数字来自本仓库的实验，不是文献引用 [20]：

| 配置 | 吞吐 | 相对单机 |
|---|---|---|
| 单台笔记本（Ryzen 9 8940HX），Qwen2.5-1.5B | 24.98 tok/s | 100% |
| 加 llama.cpp RPC 层，本机回环 | 20.28 tok/s | 81% |
| 把一部分层放到手机（天玑 9200），2.4 GHz Wi-Fi | 3.40 tok/s | 14% |

拆解：**架构税约 19%，网络税约 83%**。往返延迟从 0.1–0.3 ms（真交换机）到 15–55 ms（2.4 GHz 随身 WiFi），差 50 倍，恰好对应 20 tok/s 与 3.4 tok/s 的差距。

**这条数字对"同协异步"的意义**：协调本身几乎免费（19%），**通信才是全部成本**。所以任何设计的第一原则不是"怎么协调得更聪明"，而是"**怎么少说几句话**"。这也解释了为什么 DeMo 必须用 MoE、为什么 Petals 要按层切、为什么本地推理永远最快。

## 5. 实验设计：Mesa 船阵

**目标**：用两小时，得到命题一和命题二的初步数据。

**工具**：Mesa（Python 的 agent-based modeling 框架）[21]。选它的理由：纯 Python、无需 GPU、结果可直接画图。

**个体规则**（三行，对应 boids）：

1. 与最近的 k 个邻居保持最小距离（分离）
2. 朝邻居的平均方向偏转 5%（对齐）
3. 若与群体质心距离超过阈值，向质心靠近（聚合）

**异步**：每一步随机打乱更新顺序，不允许同时更新。这一步是"同协异步"与经典 boids 的全部区别。

**变量**：

| 变量 | 取值 |
|---|---|
| N | 20, 50, 100 |
| k | 2, 3, 5, 8 |
| 偷懒比例 | 0%, 5%, 10%, 20%, 30%, 50% |
| 随机种子 | 每格 100 次 |

**指标**：

- **成队步数**：从初始随机位置到"所有船的方向方差 < 0.05"所需步数
- **成队率**：100 次里成功的比例
- **崩溃率**：注入偷懒节点后，队形散掉（方向方差 > 0.3）的比例
- **恢复时间**：随机踢掉 20% 节点后，重新成队所需步数

**预期**（可被推翻）：k=3 时开始出现稳定队形；偷懒比例超过 20% 后崩溃率断崖上升。

**产出**：一个 `sim/` 目录、一张"偷懒比例—崩溃率"的图、一段可复现的命令。**没有代码就没有结论**——这是本仓库从上一个项目学到的教训。

## 6. 还没被回答的

1. **异构性**：文献里的个体大多同质。真实场景里，一台十年前的笔记本和一台新手机，在同一套规则下会不会互相拖累？
2. **动机**：Ostrom 的八条原则是给人类的。能不能翻译成代码里的奖励规则？
3. **"进度不同"到什么程度还有意义**：如果最快的节点要等最慢的节点，异步就成了负担。这个临界点在哪？
4. **规模**：从 3–5 人到 1000 人，规则要不要换一层？Ostrom 的"嵌套层级"暗示要。

这四个问题，任何一个都可以单独成为一篇小论文。
